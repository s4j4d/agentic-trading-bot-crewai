# Sub-15-minute full-cycle plan — crypto_council_flow `--once`

## Goal
Make `python -m crypto_council_flow.main --once` finish in under 15 minutes wall-clock on the laptop, so it can be re-run on a tight infinite loop.

## Current context / assumptions
- Project root: `C:/Users/mmmsm/Programming/trading-bot-crewai/crypto_council_flow` (run all commands from here; interpreter is `.venv/Scripts/python`).
- Entry: `src/crypto_council_flow/main.py` — `CryptoCouncilFlow` with `run_scout` → `analyse_coins` → `manage_portfolio`; scheduler `_run_async()`; CLI parsed by `_parse_inputs()`.
- Crews: `src/crypto_council_flow/crews/council/council_crew.py` — `CouncilScoutCrew` (1 agent, `max_iter=15`), `CouncilAnalysisCrew` (technical → sentiment → risk, sequential), `CouncilPortfolioCrew` (1 agent).
- Task prompts: `src/crypto_council_flow/crews/council/config/scout_tasks.yaml`, `analysis_tasks.yaml` (technical uses 5 indicators, sentiment does fear/greed + 10 news + community + dominance, risk does sizing + liquidation + VaR + correlation), `portfolio_tasks.yaml`.
- Agents: `src/crypto_council_flow/crews/council/config/agents.jsonc` (reasoning flags; code currently forces `reasoning=False` on most agents in `council_crew.py`).
- Timing instrumentation already exists: `CYCLE SUMMARY`, per-coin `⏱`, `**Analysis time:**` in `output/*_report.md`, `duration_s` in `output/portfolio_plan.json` + `output/portfolio_history.jsonl`.
- Tool HTTP already hardened: every tool `_DEFAULT_TIMEOUT = 10`; `tools/technical_indicators.py` has a 15-min OHLC cache + 6 s CoinGecko gap (`_throttled_get`, thread-safe lock).
- Baseline (observed): toman `--once --account-size 5000000 --base-currency toman` analysed ~10 coins at ~4–6 min/coin → ~35–60 min total. LLM inference dominates; tool latency is second-order.
- LLM serving is assumed local/slow (Ollama `qwen3:14b` referenced for CrewAI memory; agent LLM comes from `.env` `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `MODEL`). If agents run on a 14b local model, ~5 min/coin × 10 coins can never fit in 15 min without fewer coins + less LLM work + parallelism.
- Tests that must stay green: `tests/test_crew_configs.py`, `tests/test_portfolio.py`, `tests/test_cycle_lock.py` (32 tests). Pre-existing unrelated failure `tests/test_backtest_30d.py::TestBacktest30Day::test_profitability` is out of scope — do not chase it.
- "Infinitely on my laptop" means: bounded memory, no overlapping cycles (existing `asyncio.Lock` stays), no new daemons/services, local-first (no paid APIs).

## Architecture / proposed approach
Cap the work (max 3 coins/cycle), shrink the LLM work per coin (fewer tools, tighter prompts, lower `max_iter`, crew time budgets, memory off by default), and parallelise the per-coin analyses with a thread pool that merges results on the main thread. Expose this as `--max-coins 3` + `--fast` flags so normal runs are untouched and the fast path is one obvious switch.

## Risks, tradeoffs, and open questions
- **Local-inference floor:** if agents run on `qwen3:14b` via Ollama with `OLLAMA_NUM_PARALLEL=1`, threads overlap I/O but token generation may still serialise — Task 8 timing is the verdict; if still >15 min, the next lever is a smaller/faster model (e.g. 7–8b) for analysis/scout via env `MODEL`, not more threads.
- **Quality loss:** 3 coins + trimmed indicators/sentiment/risk narrows coverage (no Bollinger squeeze, no community health, single leverage). Mitigation: `--fast` is opt-in; default path keeps full depth.
- **Parallel + rate limits:** distinct coins still each fetch OHLC/news; the 6 s CoinGecko gap serialises misses (fine) but 3 workers × news endpoints could 429 — tasks instruct agents to move on; cache + 10 s timeouts already bound the damage.
- **Portfolio staleness (if 8c applied):** skipping portfolio every other cycle delays exits by one cycle — acceptable for paper trading, flagged in console when skipped.
- **Laptop thermals:** infinite tight loops pin CPU/GPU; recommend a sleep (e.g. 60–120 s) between `--once` iterations in the wrapper script, not in this plan.
- Open questions for the user: (1) Which model actually serves the agents — env `MODEL` (remote?) or local Ollama 14b? (2) Is dropping from ~10 to 3 coins/cycle acceptable for the infinite-run use case? (3) May portfolio run every 2nd cycle in fast mode, or must every cycle rebalance?
